# Запуск веб-парсера на Railway

Сервис показывает форму с URL каталога, числом страниц и единицами длины. Сбор работает в фоне; по завершении доступно скачивание XLSX. Подробный журнал обхода и исходные значения находятся внутри книги. Вход защищён HTTP Basic Auth; в браузере появится стандартный запрос логина и пароля.

## Настройка

1. Отправьте подготовленные файлы проекта в GitHub и создайте в Railway сервис **Deploy from GitHub repo**, выбрав этот репозиторий. Корень сервиса — корень репозитория. Railway использует `Dockerfile` и `railway.json`.
2. В Variables задайте `WEB_PASSWORD` — собственный длинный пароль. Логин по умолчанию `admin`; для другого логина задайте `WEB_USERNAME`. Пароль не помещайте в Git.
3. Подключите Volume с Mount Path `/data`. В нём сохраняются статусы и XLSX. Без Volume результаты исчезнут при пересоздании контейнера.
4. В Networking создайте публичный домен Railway. `PORT` предоставляет Railway; приложение слушает `0.0.0.0:$PORT`. Собственную Start Command задавать не требуется.
5. После успешного healthcheck `/health` откройте домен, войдите и выполните первый обход с лимитом 5–10 страниц.

`/health` возвращает 503, если `WEB_PASSWORD` отсутствует. Он не запускает парсинг. При ошибке запуска смотрите Deployment Logs.

## Переменные

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `WEB_PASSWORD` | нет, обязательна | Пароль для страницы и API |
| `WEB_USERNAME` | `admin` | Логин |
| `DATA_DIR` | `/data` | Каталог постоянных результатов |
| `PORT` | `8080` | HTTP-порт; Railway задаёт автоматически |
| `PARSER_BROWSER` | `requests` | `requests`, `auto` или `playwright` |

По умолчанию образ поддерживает статические HTML-сайты. Для сайтов с JavaScript задайте Railway build variable `INSTALL_PLAYWRIGHT=true` (Dockerfile ARG), пересоберите образ и задайте runtime variable `PARSER_BROWSER=playwright` либо `auto`. Это устанавливает Chromium и системные зависимости, увеличивая образ. Браузерный режим отдельно не проверен в текущей среде.

## Выполнение и хранение

- Используйте **одну реплику и один Gunicorn worker**. В образе уже заданы один worker и четыре HTTP-потока. Локальная блокировка ограничивает сбор одним заданием одновременно; второй запуск получает HTTP 409.
- Статус сохраняется в `/data/jobs/<id>/status.json`, результат — в `/data/jobs/<id>/plants.xlsx`. Завершённые файлы можно скачать по прежнему URL после перезапуска, если подключён Volume. ID последнего задания сохраняется в браузере, чтобы восстановить статус и ссылку после обновления страницы.
- При деплое или перезапуске незавершённое задание помечается ошибкой и требует повторного запуска. Очереди и автоматического продолжения обхода нет.
- Файлы автоматически не удаляются: следите за местом на Volume и удаляйте ненужные завершённые каталоги.
- История страниц хранится в `/data/crawl.sqlite3` отдельно от заданий. Удаление папки задания не сбрасывает историю. Повторный запуск продолжает обход и экспортирует накопленные растения этого сайта. Для полного сброса остановите сервис и сохраните резервную копию базы перед её удалением.
- В XLSX добавлен лист `Source pages`: полные исходные тексты и HTML карточек. Журнал доступен для скачивания и при пустом результате. Интерфейс различает новые загрузки и использование истории.
- Лимит формы — 1–500 страниц, задержка запросов — 0.5 секунды. robots.txt соблюдается. Если часть страниц недоступна, результат содержит число ошибок и Crawl log. Если растения не найдены, скачивание не предлагается.

## Локальная проверка

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m unittest discover -v

# Задайте WEB_PASSWORD в окружении перед запуском.
DATA_DIR=/tmp/plant-parser-data .venv/bin/gunicorn \
  --bind 0.0.0.0:8080 --workers 1 --threads 4 'web:create_app()'
```

Контейнер:

```bash
docker build -t plant-parser .
# WEB_PASSWORD должен быть задан в текущем окружении.
docker run --rm -p 8080:8080 -e WEB_PASSWORD \
  -v plant-parser-data:/data plant-parser
```

Проверка после запуска: `curl --fail http://127.0.0.1:8080/health`.


API использует тот же Basic Auth: `POST /api/jobs` с JSON `{"url":"https://example.com/plants","max_pages":10,"display_unit":"m"}`, затем `GET /api/jobs/<id>` и `GET /api/jobs/<id>/download`. Пароль передавайте через безопасную конфигурацию клиента.
