# Разбор фактического результата Greeninfo

После аудита внесены исправления: профиль карточек Greeninfo, фильтрация медиа и служебных разделов, SQLite-история и экспорт полного содержимого в `Source pages`. Живая разметка сайта по-прежнему требует отдельной проверки; регрессионные HTML-примеры в тестах синтетические.

Источник: `https://www.greeninfo.ru/decor_trees/cornus_alba.html`.
Результат: `plants-6f1be2bddfeb4d9882ab505e050d1f3c.xlsx`.

Проверены все пять листов XLSX; показатели ниже вычислены из строк журнала и evidence. Живой HTML сайта в этой облачной среде недоступен: CONNECT к домену блокируется прокси с HTTP 403. Это ограничение текущей проверки, а не ошибка сайта в предоставленном запуске. В загруженном журнале 403 нет.

### 1. Исходная карточка пропущена

Первая строка Crawl log: `cornus_alba.html`, HTTP 200, заголовок «Дерен белый», тип `catalog/other`. Поэтому `build_plant_record` для этой страницы вообще не вызывается. Данные исходного растения не проходят ни извлечение, ни сопоставление, ни экспорт.

Ещё шесть видовых карточек загружены с HTTP 200, но также исключены: `cornus_alternifolia.html`, `cornus_kousa.html`, `cornus_canadensis.html`, `cornus_sanguinea.html`, `cornus_mas.html`, `cornus_stolonifera.html`. Страница рода `cornus.html` тоже имеет `catalog/other`; её надо отличать от видовых карточек, а не автоматически считать самостоятельным видом.

**Вывод:** переходы к следующим видам уже происходили, но последующее распознавание карточек отвергало результат. Только изменение очереди ссылок эту проблему не устранит.

### 2. Все 14 ошибок связаны с изображениями

Это URL из `/img/work/catalog/` с расширениями `.jpg` и `.JPG`. Они попали в HTML-очередь, после чего `_fetch_requests` отверг MIME `image/jpeg`.

В данном журнале нет свидетельств тайм-аутов, блокировки сайта, ошибки SSL или необходимости Playwright. Неизвестные HTTP-коды у JPEG нельзя подменять предположением, но фактическая причина исключения записана однозначно: неподдерживаемый для HTML тип содержимого.

**Исправление:** исключать медиа до постановки в очередь HTML; сохранять их URL как изображения с источником и подписью. Для URL без расширения использовать ответ Content-Type: не-HTML ресурс классифицировать отдельно, не повторять как сетевую ошибку. Лимит HTML-страниц не расходовать на файлы изображений.

### 3. В основную базу попали посторонние страницы

| Строка | URL / тип страницы |
| --- | --- |
| `PLT-E37B63617D4B` | `https://www.greeninfo.ru/` — главная |
| `PLT-97216EE5B3AB` | `cornus.html/Social` — сообщество рода |
| `PLT-B86176B319BB` | `cornus_alba.html/Forum` — форум |
| `PLT-9C01DD3F8DEB` | `…/miniatyurnye-rasteniya-dlya-malenkogo-sada_art.html` — обзорная статья |

**Исправление:** профиль Greeninfo должен различать карточку вида/сорта, страницу рода, каталог, форум, сообщество и редакционную статью. `/Forum`, `/Social`, `/Article` и `_art.html` не должны становиться самостоятельными растениями. При необходимости редакционные статьи можно привязывать как дополнительные источники явно определённого растения, сохраняя происхождение данных.

### 4. Найдено ложное сопоставление с высокой уверенностью

Единственное принятое содержательное значение:

- raw label: `Использование удобрений`;
- raw value: ` помогая - не навредить`;
- target: `Тип насаждений`;
- normalized: `помогая - не навредить`;
- confidence: `0.96`;
- source: обзорная статья о миниатюрных растениях.

Причина в коде: широкое совпадение с alias «использование» и разрешение произвольного текста для `enum_or_text`, без достаточной проверки объекта высказывания. Извлечение по всей странице дополнительно подбирает посторонние заголовки и подписи.

**Исправление:** ограничить извлечение содержимым конкретной карточки; убрать семантически чрезмерные совпадения или добавить обязательный контекст применения растения. Проверить на регрессии, что использование удобрений не является типом насаждений. Не снижать глобальные пороги уверенности.

### 5. Расшифровка 49 отклонений

| Причина | Количество |
| --- | --- |
| Не найдено правило поля | 37 |
| Русское название из заголовка имеет недостаточную уверенность | 8 |
| Неоднозначно: летняя или осенняя окраска | 2 |
| Парсер не нашёл допустимого значения | 2 |

Эти отклонения относятся к четырём ошибочно выбранным страницам, а не к исходной карточке дерена. Среди «признаков» — подписи форумных тем, материалы о подсветке, видео и другие посторонние элементы. Поэтому 49 отклонений нельзя интерпретировать как 49 пропущенных характеристик дерена.

Два неоднозначных значения: label «Окраска», value «Дерен белый», источники `/Social` и `/Forum`. Это не характеристика цвета листьев. Снимать защиту от неоднозначности здесь неправильно.

### 6. Повторы и счётчики

В этом запуске все 50 URL различны: повторных строк Crawl log нет. Проблема — низкая релевантность выбранных URL и отсутствие реестра между запусками. Наличие 388 изображений в evidence не означает 388 уникальных изображений и не доказывает дублирование основной карточки.

Сообщение «4 растения» недостоверно: это четыре записи, ошибочно признанные растениями. После исправления классификатора число растений в этом старом результате не становится автоматически равным семи: семь видовых страниц надо действительно разобрать и проверить.

## Корректировка реализации под новые требования

1. **Распознавание Greeninfo:** разбирать стартовую видовую карточку до обхода боковых разделов; выделять заголовок, ботаническое имя и основной блок по фактической разметке сайта. Самого URL и одного упоминания растения недостаточно.
2. **Полнота:** сохранять основной текст, таблицы, пары свойств, списки и изображения независимо от попадания в целевую схему. Хранить оригиналы и произвольные признаки, затем выполнять строгую нормализацию.
3. **Ссылки следующего растения:** использовать подпись ссылки и раздел, в котором она найдена. Ссылки соседних видов ставить в приоритетную очередь; форум, сообщество, файлы и навигацию исключать. Данные соседних растений не смешивать с текущим.
4. **Постоянная история:** SQLite на `/data`, канонический URL и алиасы редиректов, состояния обработки, время, причина исключения/ошибки, хеш содержимого. Успешно обработанные страницы пропускать между запусками, ошибки сохранять для контролируемого повтора. Экспортировать накопленную базу.
5. **Качество:** не считать технические ID/URL/дату заполненной карточкой. Страницы без подтверждённой карточки и признаки без достаточного контекста не должны повышать число растений или confidence.
6. **Диагностика:** раздельные счётчики HTML, растений, файлов, пропусков и ошибок; журнал доступен даже при пустом результате. Вместо безусловного «Готово» — частичный результат или ошибка извлечения, если содержательные данные отсутствуют.

## Проверка исправленной версии

- Исходный `cornus_alba.html` распознаётся как карточка, а её реальные признаки совпадают с содержимым страницы.
- Шесть указанных соседних видов обрабатываются как самостоятельные карточки; главная, форум, сообщество и обзорная статья не создают ложные растения.
- Ссылки `.jpg`/`.JPG` не отправляются в HTML-парсер и не создают прежние 14 ошибок.
- Подпись «Использование удобрений» не заполняет «Тип насаждений».
- Повторный запуск с тем же Volume не скачивает заново успешно обработанные страницы и не добавляет повторные сведения.
- Полнота подтверждается сравнением с HTML реальных карточек, а не только синтетическими примерами. Для такой проверки нужен доступ к сайту из среды разработки или сохранённые HTML карточки.
