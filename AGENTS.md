# Инструкции для работы с plant_parser

## Проект

Python CLI для сбора карточек растений с одного домена, строгого сопоставления признаков, нормализации единиц и экспорта XLSX. Подробное описание: `README_plant_parser.md`.

- `plant_parser_production.py` — модели данных, парсеры значений, правила полей, извлечение HTML/JSON-LD, обход сайта и экспорт.
- `База_растений_финальная_схема.xlsx` — исходная схема базы. Не перезаписывайте её результатами запуска.
- `README.md` — краткое описание проекта.
- `web.py`, `templates/index.html` — защищённая паролем веб-страница, API заданий и скачивание XLSX.
- `Dockerfile`, `railway.json`, `RAILWAY.md` — развёртывание веб-сервиса на Railway. Один worker и одна реплика; данные в `/data` на Volume. Для запуска нужен `WEB_PASSWORD`.

## Зависимости и запуск

Работайте из корня репозитория. Используйте существующий checkout; отдельный worktree без запроса пользователя не нужен.

Зависимости перечислены в `requirements.txt`, проверки находятся в `test_parser_core.py` и `test_parser_regressions.py`. Lockfile пока отсутствует.

При необходимости создайте виртуальное окружение и установите зависимости, найденные в импортах:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python plant_parser_production.py --help
```

Для браузерного режима дополнительно нужны `playwright` и Chromium (`.venv/bin/python -m playwright install chromium` после установки пакета). Режим `--browser requests` не требует браузера.

Пример запуска; замените URL на реальный адрес нужного каталога:

```bash
.venv/bin/python plant_parser_production.py \
  --url "https://example.com/catalog/plants" \
  --browser requests --max-pages 5 --output /tmp/plants.xlsx
```

Соблюдайте robots.txt и задержки запросов. `--ignore-robots` используйте только при наличии разрешения. Не запускайте массовый обход как побочный эффект обычной проверки кода.

## Правила изменений

- Сохраняйте raw-значения, min/max, исходные единицы, URL, evidence и confidence, включая отклонённые observations.
- Канонические единицы: длина — метры, объём — литры, температура — °C. Не конвертируйте валюты автоматически.
- Не смешивайте взрослую высоту и высоту саженца, USDA и температуру морозостойкости, влажность почвы и устойчивость к переувлажнению, размер контейнера и пригодность к кашпо.
- Не выдумывайте отсутствующие данные; сохраняйте несколько наблюдений и исходные диапазоны.
- Для подписей конкретного сайта предпочитайте поддерживаемый `--rules-overrides` JSON общим изменениям смысловых правил.
- Сохраняйте структуру экспортируемых листов и чёрно-белое оформление, если задача не требует другого.
- Следуйте существующему стилю: типизация, dataclasses, snake_case для функций и UPPER_CASE для констант.
- Не добавляйте в коммиты виртуальное окружение, кэши, секреты и результаты обхода.

## Проверка изменений

Минимальная проверка синтаксиса без генерации файлов:

```bash
python3 -c "import ast, pathlib; ast.parse(pathlib.Path('plant_parser_production.py').read_text(encoding='utf-8'))"
```

После изменений поведения проверяйте затронутые парсеры и экспорт на локальных примерах HTML/значений. Для исправлений ошибок добавляйте осмысленные регрессионные тесты. Запускайте `.venv/bin/python -m unittest discover -v`.

Проверка синтаксиса и `--help` не доказывают корректность сбора и экспорта. В отчёте различайте выполненные проверки и непроверенные сценарии. Перед завершением просмотрите `git diff` и `git status --short`.
